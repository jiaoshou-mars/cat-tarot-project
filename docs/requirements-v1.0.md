## 1. 产品概述

### 1.1 产品定位

一款以"猫咪塔罗"为主题的轻量占卜网站：用户提出一个当下的困惑，系统确定性抽取一张猫咪塔罗牌，先给出官方牌义，再由 AI 以"温柔的猫咪占卜师"口吻生成个性化解读，并在 AI 不可用时无缝回退本地解读。

### 1.2 目标用户

- 遇到小决策或情绪波动、希望获得一个温和视角的普通用户
- 喜欢猫咪与塔罗文化、把占卜当作情绪陪伴工具的用户

### 1.3 核心价值

- **确定性 + 灵感性**：同一问题在同一天内抽牌结果稳定（可复现、不折腾），解读内容则由 AI 个性化生成
- **永不空白的结果页**：官方牌义始终可见；AI 失败自动回退本地模板解读，页面不会空白或报错
- **仪式感体验**：视口中央多圈洗牌 → 最后一转揭晓 → 结果页落位的完整抽牌仪式动画

## 2. 产品范围

### 2.1 本期包含

1. 首页 / 导航
2. 塔罗测算（问题输入 → 抽牌仪式 → AI 解读结果页）
3. 图鉴（78 张标准牌 + 5 张艺术卡的筛选浏览与详情）
4. AI 解读服务（服务端代理调用大模型，结构化输出 + 本地兜底）

### 2.2 本期明确不做

- 账号系统、历史记录持久化
- 支付、多语言、复杂分享图
- 多张牌阵（牌阵库数据已预置，本期不启用）
- 三灵共鸣等衍生玩法

## 3. 功能需求

### 3.1 首页 / 导航

- FR-1.1 顶部导航包含三个入口：首页、塔罗测算、图鉴；当前页高亮
- FR-1.2 首页展示产品介绍与进入测算的引导入口

### 3.2 塔罗测算流程

#### 3.2.1 问题输入

- FR-2.1 用户输入问题（必填，1–120 字，实时字数统计）
- FR-2.2 提供"加入小阿卡纳"开关，**默认开启**；开启后抽牌池从 22 张大阿卡纳扩展到全部 78 张
- FR-2.3 未输入问题时抽牌按钮禁用；仪式进行中输入区与开关锁定
- FR-2.4 提问态右侧常驻显示卡背预览，保证核心牌卡元素可见

#### 3.2.2 抽牌规则（确定性）

- FR-2.5 抽牌由确定性算法完成，不由 AI 决定：`seed = hash(问题文本 + 当天日期 + 牌池标识)`，基于 seed 从对应牌池均匀抽一张，并按 seed 派生正/逆位
- FR-2.6 同一问题在同一天、同一牌池设置下重复抽牌结果一致；"再测一次"回到输入态并保留问题
- FR-2.7 AI 只负责解读抽中的牌，不得重新抽牌、换牌或声称看到其他牌（服务端强制）

#### 3.2.3 抽牌仪式动画

- FR-2.4 流程分四阶段：`flipping`（多圈旋转，全程只见卡背）→ `revealing`（最后一转翻到真实牌面）→ `revealed`（牌面稳定停留约 0.8 秒，同时开始请求 AI 解读）→ `result`（进入结果页）
- FR-2.8 仪式层以真实视口居中定位（不受页面滚动影响），桌面短屏与移动端均完整可见
- FR-2.9 仪式阶段锁定页面滚动，退出时恢复
- FR-2.10 动画期间不显示任何可见过程文案（避免与卡牌重叠）；仅保留 1×1px 屏幕阅读器专用状态播报
- FR-2.11 系统开启"减少动态效果"时，动画缩短为极短等待（约 0.1–0.5 秒），仍完整经历卡背→牌面→结果

#### 3.2.4 结果页

- FR-2.12 左侧为抽中牌面（含正/逆位标识），右侧为摘要区：牌名、正逆位、用户问题回顾、能量值（0–100）、关键词标签（最多 6 个）
- FR-2.13 **官方牌义卡片始终立即显示**（正/逆位对应的牌义解读原文），不依赖 AI 状态
- FR-2.14 AI 解读三段式：猫咪视角 / 局势分析 / 行动建议，附一句安抚文案
- FR-2.15 AI 请求进行中：解读区显示"猫咪正在细读牌面"加载态（含动效），能量值显示占位符
- FR-2.16 AI 失败/超时：渲染本地模板解读，显示克制提示"本次先使用本地牌义为你解读"，并提供"重新获取解读"按钮（同一张牌重新请求，不重新抽牌）
- FR-2.17 操作按钮：再测一次（保留问题）、换个问题（清空）
- FR-2.18 竞态保护：重抽、换问题、离开页面均取消进行中的 AI 请求；迟到响应不得覆盖新结果

### 3.3 AI 解读服务

#### 3.3.1 接口契约

- FR-3.1 前端仅请求同源相对路径 `api/divination`，经开发代理或网关反向代理转发到本地 API 服务；前端代码不包含模型厂商地址、模型名或密钥
- FR-3.2 请求字段：问题（1–120 字）、牌 ID（两位数字）、方向（正/逆位）、是否含小阿卡纳、抽牌种子；请求体上限 16KB
- FR-3.3 成功响应：状态（success/fallback）、来源（ai/local）、结构化结果（牌头、能量值、三段解读、安抚文案）、请求 ID
- FR-3.4 回退响应额外携带原因枚举：超时 / 限流 / 模型不存在 / 服务商错误 / 响应无效 / 配置错误；前端只展示温和提示，不暴露服务商细节

#### 3.3.2 解读生成规则（Prompt 业务规则）

- FR-3.5 系统角色：温柔、神秘但不吓人的猫咪塔罗占卜师
- FR-3.6 只解读服务端指定的牌与方向；不得重新抽牌、替换牌面或声称看到其他牌
- FR-3.7 提供情绪支持、视角启发和可执行建议，不得声称确定预测未来
- FR-3.8 问题涉及医疗、法律、金融、人身安全或自伤风险时，明确建议咨询专业人士或寻求现实帮助
- FR-3.9 简体中文输出，语气温暖自然，不制造恐惧、依赖或宿命感
- FR-3.10 Prompt 中注入：用户问题、指定牌名、指定方向、关键词、官方牌义原文
- FR-3.11 输出为纯 JSON 对象（六个规定字段），禁止 Markdown 代码块与额外说明

#### 3.3.3 服务端安全与可靠性

- FR-3.12 密钥仅存于服务端外部配置文件（不进代码仓库、构建产物、日志与响应）；配置支持更换文件路径与服务商地址；配置缺失不阻止服务启动，接口自动回退本地解读
- FR-3.13 服务端根据牌 ID 从本地牌库重新取牌义，不信任前端提交的任何牌义或 Prompt
- FR-3.14 AI 返回的牌头由服务端按真实牌面覆写，模型无法声称抽到别的牌
- FR-3.15 结构化结果严格校验：字段齐全、无额外字段、能量值 0–100、各文本非空且限长
- FR-3.16 调用超时（服务端 15 秒 / 客户端 20 秒）、HTTP 错误、无效 JSON、校验失败均回退本地解读
- FR-3.17 基础防护：按 IP 限流（默认 12 次/分钟）、并发上限（默认 3）、超限直接返回本地结果
- FR-3.18 日志仅记录请求 ID、状态、模型、耗时、token 数与错误类别；不记录密钥、完整问题与完整 Prompt
- FR-3.19 前端结果不包含调试用 Prompt 字段

### 3.4 图鉴

- FR-4.1 筛选维度：全部 / 大阿卡纳 / 权杖 / 圣杯 / 宝剑 / 星币 / 艺术卡
- FR-4.2 "全部"视图包含 78 张标准牌 + 5 张艺术卡（共 83 张）
- FR-4.3 标准牌卡片展示牌面、中文名、类别；点击打开详情弹窗（大图 + 正位/逆位关键词与牌义）
- FR-4.4 艺术卡卡片展示画面与标题；点击打开大图弹窗（等比完整显示原图）
- FR-4.5 响应式列数：宽屏 5 列 → 1040px 4 列 → 820px 3 列 → 560px 2 列
- FR-4.6 卡片视觉统一：单一深色牌身底色 + 暖金标题 + 单层低对比外框，hover 抬升，键盘焦点可见

## 4. 非功能需求

- NFR-1 **性能**：AI 解读常规耗时 4–10 秒，期间页面非阻塞；静态资源本地构建、懒加载图鉴图片
- NFR-2 **降级**：AI 服务任何故障路径下结果页均完整可用（本地解读兜底），无空白页
- NFR-3 **安全**：密钥隔离（见 FR-3.12/3.18）；请求体大小限制；无密钥、无服务商细节泄露到浏览器端
- NFR-4 **可访问性**：支持系统"减少动态效果"；屏幕阅读器可感知抽牌阶段状态；弹窗与卡片支持键盘操作
- NFR-5 **兼容性**：现代桌面与移动浏览器；布局适配 390px 起的移动视口
- NFR-6 **可部署性**：支持子路径部署（前端使用相对 API 路径）；前端静态产物与 API 服务可分离部署

## 5. 技术架构约束

- 前端：Vite + React + TypeScript，单页应用（状态切换式导航，无 URL 路由）
- 服务端：Node + Express + Zod，原生 fetch 调用 OpenAI 兼容接口（默认 DeepSeek，模型与地址可配置）
- 前后端共享：牌库数据、Prompt 构建、本地解读模板（单一实现，不复制两份）
- API 服务监听本机回环地址，由网关（开发时 Vite 代理 / 生产时 Nginx）同源反代

## 6. 验收基线（v1.0 已验证）

1. 三条浏览器端自动验收：抽牌仪式各阶段定位与动画、图鉴 83 张与响应式列数、结果页要素完整
2. AI 真实调用：结构化解读字段完整、牌面/方向与官方牌义一致、耗时与 token 正常
3. 故障注入：配置缺失、超时、限流、无效请求均正确回退或拒绝，结果页不空白
4. 竞态验证：重抽/换问题后旧请求被取消，不覆盖新结果
5. 安全扫描：代码仓库、构建产物、日志与响应中无密钥材料
